# 実装引き継ぎ書(handoff.md)

作成: 2026-08-10(仕様凍結と同日)/ 作成者: spec-loop 司令塔
実装担当の想定: 別セッションの Sonnet。本書のみで着手できる自己完結を意図する。

## 1. 何を作るか(1段落)

「今夜、外に出れば Starlink が見えるか」に即答する Web アプリ。完全静的サイト+
ブラウザ内 SGP4 計算。打ち上げ直後トレインを優先しつつ 5 日分の可視パス予報を表示する。
日本語のみ・モバイルファースト。デザインは案A「Mission Control」で確定済み。

## 2. 前提資料(すべて必読。パスはプロジェクトルート相対)

- `docs/spec/20260810-starlink-visibility/spec.md` — 凍結済み仕様(状態行を確認すること)
- `docs/spec/20260810-starlink-visibility/decisions.md` — 決定 D-001〜D-013 と理由
- `docs/spec/20260810-starlink-visibility/design-brief.md` — 画面構成・トークン・コピー文言の正
- `docs/spec/20260810-starlink-visibility/review.html` — 採用済みモックアップ(案A部分が視覚の正)

実測済みの事実(2026-08-10 検証、再検証不要):
- CelesTrak GP API `https://celestrak.org/NORAD/elements/gp.php?GROUP=starlink&FORMAT=json`
  は `Access-Control-Allow-Origin: *` 付き。約4.36MB・約10,913衛星。
- 各レコードに `OBJECT_ID`(COSPAR 識別子、例 "2019-074B")あり。打ち上げ単位の
  グループ化に使う。
- CelesTrak への再取得は2時間以上間隔を空ける(運用者への配慮。実装で強制すること)。

## 3. 技術スタック(推奨。変更する場合は理由を記録して報告)

- Vite + TypeScript、UI フレームワークなし(vanilla DOM)。静的出力(D-004)
- SGP4: `satellite.js` / 太陽位置: `suncalc` / テスト: Vitest
- 方位図は inline SVG(design-brief.md §1 の仕様どおり)
- Node/npm(Python は使わない。使う場合は uv 経由+PYTHONUTF8=1)

## 4. Sprint 分解(1 Sprint = ユーザーに説明できる1つの価値)

| # | 価値(ユーザー向け説明) | 依存 |
|---|---|---|
| S1 | 地点を設定・保存できるアプリの殻(デザイントークン・減光トグル込み) | なし |
| S2 | 設定地点の「今夜見えるか」verdict と5日分パス予報が見られる | S1 |
| S3 | 各パスの方位図で「どこを見ればいいか」が分かる | S2 |

## 5. 共通ルール(全 Sprint に適用)

### 触ってよいファイル
- プロジェクトルート直下の実装物: `src/`, `public/`, `index.html`, `package.json`,
  `vite.config.ts`, `tsconfig.json`, `.github/workflows/`, `.gitignore`, `README.md`
- S1 冒頭で `git init` し、以後 Sprint ごとに小さくコミットする

### 触ってはいけないファイル
- `docs/spec/20260810-starlink-visibility/` 配下すべて(凍結済み。参照のみ。
  仕様変更が必要になったら実装せず停止し、ユーザー承認を経て司令塔が更新する)
- `thinking-dashboard/` (別ツール。本プロジェクトと無関係)
- `.env`(読み取りも変更も禁止)

### 検証の共通手順(各 Sprint の合格判定に使う)
- 実行環境: 本プロジェクトディレクトリ内で完結(隔離条件: 他セッション・他プロセスと
  共有するリソースなし。S5 のみ例外、後述)
- `npm run dev` → ブラウザで `http://localhost:5173`(Vite 既定)を開き実機確認
- `npm run test`(Vitest)が exit 0 / `npm run build` が exit 0
- 失敗の見え方の典型: CORS・fetch 失敗は DevTools console にエラー、SGP4 の時刻ずれは
  予報が数時間ズレる(UTC/JST 混同が最頻出。内部計算は UTC、表示のみ JST に統一)、
  cp932 問題はテスト出力の文字化け(テスト名・console 出力は ASCII 主体にする)
- ブラウザ実機確認には claude-in-chrome または playwright を使う。使えない場合は
  弱い検証に黙って差し替えず、その旨を報告してから代替を提案する

### エスカレーション基準(F1〜F5。該当時は義務)
- F1【行き詰まり】同一問題への修正2回失敗、または仮説2回反証 → 3回目の変種を試さず、
  エラーログ全文+試行履歴を添えて Fable(Agent ツール model:"fable")に根本原因分析を委譲
- F2【判断】凍結仕様の変更が必要と判明・後戻り困難なトレードオフ・セキュリティ判断
  → Fable に委譲。仕様変更はさらにユーザー承認必須(勝手に実装しない)
- F3【品質ゲート】各 Sprint の完了報告前に、実装と別パスのレビューを1回挟む
  (codex exec(stdin は `< /dev/null` でリダイレクト)または Fable への依頼。
  自己レビューのみで完了にしない。コミット前までに実施)
- F4【共有リソース】GitHub リポ作成・Vercel 連携・実機ブラウザ往復はサブエージェントに
  委譲しない(本体で同期実行)。やむを得ず委譲する場合は隔離(別ディレクトリ・
  別セッション名)と成果物契約(diff・テスト実出力・未検証項目の明示)を依頼文に明記
- F5【実機往復の行き詰まり】ブラウザ確認ループで詰まったら委譲でなく
  「/model で本体を一時的に Fable へ切替」をユーザーに提案

### 報告の作法
- 「実装済み/テスト済み/実機検証済み」のどこまで済んだかを明示し、届いていない段階は
  「未検証」と書く。無修飾の「完了」は使わない

## 6. Sprint 詳細

### S1: アプリの殻+観測地点(D-005, D-009)

- 内容: Vite+TS 雛形、デザイントークン実装(bg #000000 / ink .92 / ink-2 .64 /
  ink-3 .40 / hairline .14 / accent #e8a33d。design-brief.md §2 と review.html 案Aが正)、
  ヘッダー+地点チップ、「現在地を使う」(Geolocation)+地名検索+緯度経度手入力、
  localStorage 保存、空状態コピー、減光トグル、非公式フッター
- 着手前の確認事項(本 Sprint 内で解消): (1) 本番フォント: D-DIN の正規無償ライセンスを
  確認、不可なら Barlow 系を self-host(D-009)。(2) 地名検索のジオコーディング先:
  Nominatim の利用規約・レート制限(1req/s)・CORS を確認し、不適合なら地名検索を
  緯度経度入力のみに縮退してユーザーに報告(D-005 の縮退はユーザー承認を取る)
- 完了条件: `npm run dev` で表示され、地点設定→リロード後も保持。減光トグルで全体輝度が
  下がる。prefers-reduced-motion 尊重・フォーカス可視。`npm run test`・`npm run build` exit 0。
  git init+初回コミット済み(コミット前に F3 レビュー)
- 検証: 実機でモバイル幅(390px)表示確認。位置情報許可ダイアログ拒否時に手入力へ
  誘導されることも確認(失敗の見え方: 拒否時に無反応なら不合格)

### S2: verdict+5日分パス予報(D-003, D-004, D-006, D-012)

- 内容: CelesTrak 直 fetch+localStorage キャッシュ(2時間ルール強制)→ satellite.js で
  SGP4 伝播 → 可視3条件判定(衛星が地平線上・太陽光照射・観測地の太陽高度で薄明判定)→
  verdict バンド(「今夜、見えます」等、コピーは design-brief.md §1)+5日分リスト
  (日時・方角・最大仰角・明るさ3段階 ●○○〜●●●。等級数値は出さない)
- データ形式: スナップショット JSON のスキーマ(必要フィールド: OBJECT_NAME, OBJECT_ID,
  EPOCH, TLE 相当の軌道6要素+B*)をこの Sprint で確定し、S5 が同じ形式を生成する
- 完了条件: 実在地点で5日分リストが表示され、可視判定ロジックに Vitest ユニット
  (太陽高度・照射判定・座標変換)が通る。妥当性の実機検証: heavens-above.com 等の
  同地点の Starlink 予報と突き合わせ、通過時刻が±5分以内(合格基準)。
  ズレが数時間なら UTC/JST 混同を疑う(失敗の見え方)
- 注意: 初回ロードの 4.36MB は S5 までの暫定として許容するが、fetch 中のローディング
  表示を必ず付ける

### S3: 方位図(D-006, D-009)— S2 後、S4・S5 と並列可

- 内容: リスト行タップで極座標 SVG を展開(外周=地平線 N/E/S/W、同心円=仰角 30°/60°、
  中心=天頂)。パス弧+開始/最大/終了の時刻ラベル。トレインは弧上ドット列。
  初回描画のみ stroke-dashoffset アニメ(reduced-motion で無効)。accent は最大仰角
  マーカーのみ(D-009 の3箇所制限を守る)
- 完了条件: 実機で方角が実際の空と整合(北を上、東西が鏡像になっていないこと=
  空を見上げた向きの図であることを必ず確認。失敗の見え方: 東西反転)。
  SVG 座標変換のユニットテストが通る

### S4: トレイン検出(D-003, D-011)— S2 後、S3・S5 と並列可

- 内容: OBJECT_ID の打ち上げ単位(例 "2025-xxx")でグループ化し、群の平均高度が
  運用高度より十分低い(目安: 平均高度 < 480km。閾値は定数化)群をトレインと推定。
  TRAIN バンドに打ち上げからの日数+「まだ明るく見える時期です」系のコピーを表示。
  明るさ目安をトレインは1段階上げる
- 完了条件: 擬似 TLE フィクスチャ(低高度群+運用高度群の混在)で検出ユニットテストが
  通る。トレイン不在期はバンドが出ないこと。実データでの実機確認は「当日トレインが
  存在する場合のみ」実施し、不在なら「フィクスチャ検証のみ・実データ未検証」と報告する

### S5: 自動更新+公開(D-010, D-013)— S2 後、S3・S4 と並列可

- 内容: GitHub Actions(cron: 日次1回+workflow_dispatch)で CelesTrak から取得→
  S2 確定スキーマの軽量スナップショット(必要フィールドのみ。目標 <1MB)を生成し
  commit → Vercel Git 連携で自動デプロイ。クライアントはスナップショット優先、
  EPOCH が古い(>24h)場合のみ直 fetch(D-010)
- 共有リソース注意(F4): GitHub リポ作成・Vercel アカウント連携はユーザー操作が必要。
  サブエージェントに委譲せず、本体で同期実行し、各外部操作の前にユーザーへ確認を取る
- 完了条件: workflow_dispatch の手動実行でスナップショットが生成・commit され、
  Vercel 本番 URL でアプリが表示・予報が出る(実機確認)。スナップショットが 1MB 未満。
  cron 設定がワークフローに存在する(日次実行の実観測は不要、手動実行の成功で代替可。
  その場合「cron 実観測は未検証」と報告する)

## 7. v1 完了の定義

S1〜S5 の全完了条件を満たし、Vercel 本番 URL で「地点設定→5日分予報→方位図→
(トレイン期なら)TRAIN 表示」が実機で通しで動くこと。最終報告には未検証項目
(cron 実観測・トレイン実データ等)を明示すること。
