# 決定記録

## D-001: SpaceX 風 DESIGN.md は「部分採用」(2026-08-10)

**背景**: ユーザーが getdesign.md(サードパーティ分析)による SpaceX 公式サイト風
DESIGN.md の採用を希望(Round 1 Q4 の回答として)。

**決定**: 全面採用はせず、トーンを翻案して拝借する「部分採用」。
オリジナルのユーティリティ UI に落とし込む。

- 採用(翻案して拝借):
  - モノクロ基調のダーク UI(純黒背景・装飾色最小)。夜間屋外利用とも親和性が高い
  - DIN 系・大文字・コンデンス気味の見出しの「雰囲気」
  - ゴーストアウトラインのピルボタン、余白の広いバンド構成
- 不採用:
  - 全面写真/動画ヒーロー、単一 CTA のマーケティング LP 型構成
  - SpaceX/ロケットを想起させる写真素材・ロゴ的要素
  - D-DIN の無確認利用(OFL 等の正規無償ライセンスが確認できれば使用可。
    確認できなければ Barlow 等の DIN 系代替フォントを使う)

**理由**:
1. 公開可能性がある(Round 1 Q1 = 自分用だが公開可能な作り)ため、SpaceX/Starlink
   公式との提携・承認があるかのような誤認リスクを避ける。対策として公式素材・
   ロゴ不使用、フッターに非公式である旨を明記する。
2. DESIGN.md は LP 向けで、観測地点指定・可視パス一覧など情報密度の高い
   ユーティリティ画面に転用できるコンポーネント体系を持たない。
3. 全面動画ヒーローは完全静的+軽量方針(Round 1 Q3 = 静的+クライアント計算)と
   相性が悪い。
4. 白大文字の強コントラストは夜間の暗順応に不利。翻案時にコントラスト調整
   (減光表示等)をモックアップで検討する。

**保留**: 翻案の具体形(トークン・画面構成)は次ラウンドの review.html
モックアップ(翻案案 2 案程度)で視覚確定する。

## D-002: 対象ユーザーは「自分用だが公開可能な作りに」(2026-08-10)

Round 1 Q1 で推奨案 (c) をユーザーがそのまま採用(異論なし)。
理由: 公開前提の要件(多言語・負荷対策等)を初期スコープに入れず小さく始めつつ、
位置情報プライバシー等は公開に耐える設計にしておき、後から公開へ昇格できるようにする。

## D-003: コア体験は「トレイン優先+通常通過も表示」(2026-08-10)

Round 1 Q2 で推奨案 (a) をユーザーがそのまま採用(異論なし)。
理由: 肉眼での「見えた!」体験の大半は打ち上げ後数日〜数週間のトレインだが、
トレイン専用にすると打ち上げの無い時期に価値ゼロになるため、通常通過予報も併載する。

## D-004: アーキテクチャは「完全静的+ブラウザ内計算」(2026-08-10)

Round 1 Q3 で推奨案 (a) をユーザーがそのまま採用(異論なし)。
satellite.js による SGP4 計算をブラウザ内で行い、GitHub Pages/Vercel 等の静的
ホスティングで配信する。
理由: 運用コストゼロ・位置情報が端末外に出ない。制約として通知機能は弱くなる
(未決10)。CelesTrak への CORS 直アクセス可否は要検証(未決6)。通知が must に
なった場合はこの決定を再検討する。

## D-005: 観測地点は「現在地+検索/手入力の併用、localStorage 保存」(2026-08-10)

Round 2 Q1 で推奨案 (a) をユーザーがそのまま採用(異論なし)。
現在地ボタン(Geolocation API)+地名検索+緯度経度手入力を併用し、localStorage に保存。
理由: 初回体験の良さと依存の少なさの両立。位置情報を端末外に出さない(D-002/D-004 と
整合)。地名検索のジオコーディング先(Nominatim 等)は無償・CORS 可否・利用規約を
実装前に確認する。

## D-006: 予報は「5日分の可視パスリスト+各パスの方位図」(2026-08-10)

Round 2 Q2 で推奨案 (a) をユーザーがそのまま採用(異論なし)。
日時・方角・最大仰角・明るさ目安をリスト表示し、各パスに空の経路を示す方位図を付ける。
理由: TLE 精度は数日で劣化し、トレインは軌道上昇中で変化が速いため 5 日超の予報は
当たらない。方位図は「どこを見ればいいか」に直結し価値が高い。

## D-007: 天気(雲量)・通知は v2 送り(2026-08-10)

Round 2 Q3 で推奨案 (a) をユーザーがそのまま採用(異論なし)。
初期リリースは軌道条件(地平線上/太陽照射/観測地が薄明〜夜)のみで可視判定する。
理由: 雲量(Open-Meteo 等)は価値が高いが初期スコープを膨らませる。通知は静的サイト
(D-004)と相性が悪く、入れるならアーキテクチャ再検討が必要。いずれも v2 候補として
スコープ外に明記する。

## D-008: 日本語のみ・モバイルファースト(2026-08-10)

Round 2 Q4 で推奨案 (a) をユーザーがそのまま採用(異論なし)。
夜間屋外でのスマホ利用を主シーンとし、モバイルファーストで設計する。
理由: 自分用スタート(D-002)なら日本語のみで十分。UI 文字列は定数分離しておき、
将来の英語化に低コストで対応できるようにする。

## D-009: デザインは案A「Mission Control」を採用(2026-08-10)

Round 3 の review.html 視覚レビューでユーザーが案Aを選択(異論なし)。案B(Pure Mono)は
不採用。
確定トークン(review.html 実装値を正とする): bg `#000000` / ink `rgba(255,255,255,.92)` /
ink-2 `.64` / ink-3 `.40` / hairline `.14` / accent `#e8a33d`。
accent の用途は3箇所に限定: verdict の時刻数値・「今夜、見えます」バッジ・方位図の
最大仰角マーカー。
見出しは DIN 系大文字(モックは Arial Narrow スタックで近似)。本番フォントは
ライセンス確認後に確定(D-DIN の正規無償ライセンスが確認できなければ Barlow 系代替)
→ 実装タスクへ引き継ぐ。
共通仕様(方位図シグネチャ・減光トグル・非公式フッター・ゴーストピル等)は
design-brief.md を正とする。

## D-010: 軌道データは「日次スナップショット同梱+古い場合のみ直 fetch」(2026-08-10)

Round 4 Q1 で推奨案 (c) をユーザーがそのまま採用(異論なし)。
GitHub Actions の日次 cron で CelesTrak GP API から取得し、必要フィールドのみ抽出した
軽量スナップショットを静的サイトに同梱。クライアントはスナップショットが古い場合のみ
CelesTrak へ直 fetch(localStorage キャッシュ・再取得は2時間以上間隔)で補完する。
理由: 実測(CORS 可だが約4.36MB・約10,913衛星)より、直 fetch 単独はモバイル初回
ロードに重すぎる(D-008)。スナップショットで初回表示速度と CelesTrak への配慮を
確保しつつ、軌道変化が速いトレイン期の鮮度を直 fetch で担保する。

## D-011: トレイン検出は「TLE のみで判定」(2026-08-10)

Round 4 Q2 で推奨案 (a) をユーザーがそのまま採用(異論なし)。
OBJECT_ID(COSPAR 識別子、実測でフィールド存在確認済み)で打ち上げ単位にグループ化し、
平均高度が運用高度より十分低い群をトレインと推定する。追加 API は使わない。
理由: 依存ゼロで D-004(完全静的)と整合。打ち上げスケジュール API(Launch Library 2
等)による「次の打ち上げ予定」表示は v2 候補。

## D-012: 明るさ表示は「3段階の目安」(2026-08-10)

Round 4 Q3 で推奨案 (a) をユーザーがそのまま採用(異論なし)。
高度・距離・太陽位相から3段階(●○○〜●●●)の目安を算出して表示する。数値等級は
表示しない。
理由: Starlink は姿勢制御・減光対策により実際の明るさの変動が大きく、数値等級は
精度の裏付けが弱い。目安表示の方が誠実で、外れた時の失望も小さい。

## D-013: ホスティングは「Vercel」(2026-08-10)

Round 4 Q4 でユーザーが選択(推奨の GitHub Pages とは異なる選択。理由コメントなし)。
構成: GitHub Actions 日次 cron がスナップショットをリポジトリに commit → Vercel の
Git 連携が自動デプロイ。サイト自体は静的配信のまま(D-004 と整合)。
整合確認(司令塔): 推奨時の「GitHub Pages 優位」は Actions との親和性を理由とした
相対比較であり、必須条件ではない。commit 起点の自動デプロイで D-010 の構成は Vercel
でも成立し、矛盾なし。副次的利点として私有リポジトリのまま運用できる(D-002 の
「自分用スタート」と整合。公開昇格時もリポ公開が必須にならない)。
留意: Vercel 無料枠のデプロイ回数制限(日次1回の自動デプロイは余裕で収まる)。
