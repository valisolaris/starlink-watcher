# review.html モックアップ構成案(Round 3 / D-001 翻案 2案)

対象: 進行役が review.html を制作するための入力。frontend-design Skill 参照済み。
制約の出典: D-001(部分採用)/ D-005〜D-008。写真・動画ヒーローと SpaceX 想起素材は使わない。

## 0. 設計の考え方(1段落)

ヒーローは写真ではなく「答え」。このアプリの存在理由は「今夜、外に出れば見えるのか?」への
即答なので、ファーストビューは可視判定の verdict(見える/見えない/次のチャンス日時)を
最大の型で置く。シグネチャ要素は「方位図(極座標の空チャート)」: 衛星観測という題材固有の
計器であり、トレインを弧上の連なる点(真珠の連なり)として描く。これを唯一の見せ場とし、
他は静かに保つ。近黒背景+酸性グリーン1色という AI 定番配色は避ける(下記のとおり
案Aは機能色アンバー、案Bは完全黒白)。

## 1. 共通仕様(両案とも)

- 画面構成(モバイルファースト、設計幅 390px、バンド構造は DESIGN.md から翻案):
  ```
  [ヘッダー] アプリ名(小・大文字・トラッキング広)+ 地点チップ「東京都○○区 ▼」
  [バンド1: VERDICT] 可視判定を最大型で。例「今夜 21:43」+ 一行説明「南西の低い空、約4分間」
  [バンド2: TRAIN] 打ち上げ直後トレインがある期間のみ出現。eyebrow「TRAIN」+ 打ち上げ名
  [バンド3: 5日分パスリスト] 行 = 日時 / 方角矢印 / 最大仰角 / 明るさ目安(点3段階)
      行タップ → 方位図(シグネチャ)を展開
  [フッター] 非公式表記 + データ出典
  ```
- 方位図(シグネチャ)の仕様: 極座標。外周 = 地平線(N/E/S/W ラベル)、同心円 = 仰角 30°/60°、
  中心 = 天頂。パスは細線の弧で、開始・最大・終了に時刻ラベル。トレインは弧上の等間隔ドット列。
  線は白の不透明度階調のみ(案Aは現在位置マーカーのみアンバー可)。inline SVG で描く。
- タイポ: 見出し/数値 = DIN 系大文字(モックは `"D-DIN", "Barlow Condensed", "Arial Narrow",
  sans-serif` のスタックで近似。本番はライセンス確認後に self-host ※未決4残項目)。
  和文本文 = `"Noto Sans JP", system-ui, sans-serif`(モックはシステムフォールバックで可)。
  時刻・角度などの数値は tabular-nums 指定。
- ボタン: ゴーストピル(1px 白枠・背景透過・大文字ラベル)。主要操作のみ塗りピル(白地黒字)。
- コピー(そのまま使用可):
  - verdict: 「今夜、見えます」/「今夜は見えません」/「次のチャンス: 8/12(水)20:15」
  - 地点: 「現在地を使う」「地点を変更」
  - 空状態: 「観測地点を設定すると、5日分の予報を表示します」
  - トレイン eyebrow: 「TRAIN」+「打ち上げから3日目・まだ明るく見える時期です」
  - フッター: 「本サイトは SpaceX 社および Starlink とは無関係の非公式ツールです。
    軌道データ: CelesTrak」
- 夜間配慮: ヘッダーに「減光」トグル(全体輝度を落とすフィルタ)。白文字の最大輝度は
  #FFFFFF でなく rgba(255,255,255,0.92) を上限にする。
- 品質床: prefers-reduced-motion 尊重、キーボードフォーカス可視、コントラスト AA。
- モーション(1箇所に集中): 初回ロードで方位図のパス弧が描画される(stroke-dashoffset)。
  他のアニメーションは付けない。

## 2. 案A「Mission Control」(機能色1色あり・データ濃度高め)

- トークン: bg `#000000` / ink `rgba(255,255,255,.92)` / ink-2 `rgba(255,255,255,.64)` /
  ink-3 `rgba(255,255,255,.40)` / hairline `rgba(255,255,255,.14)` /
  accent `#E8A33D`(減光アンバー。天文の赤色ライト文化に接続する機能色)
- accent の用途を3つに限定: verdict の時刻数値、「今夜、見えます」バッジ、方位図の
  最大仰角マーカー。それ以外は白階調のみ。
- リストは罫線(hairline)区切りで密度高め。計器盤・管制室の趣。

## 3. 案B「Pure Mono」(DESIGN.md に忠実な完全黒白・余白広め)

- トークン: bg `#000000` / 白の不透明度階調のみ(.92 / .64 / .40 / .14)。色は一切使わない。
- 状態は色でなく「型」で符号化: 見える = 塗りバッジ(白地黒字)+大ウェイト、
  見えない = アウトラインバッジ+通常ウェイト。
- バンド間余白を案Aの約1.5倍に。verdict の型をさらに大きく(80px 相当を clamp で可変)。
  1バンド1メッセージの LP 的呼吸を、写真なしで余白と型だけで再現する。

## 4. review.html 実装メモ(進行役向け)

- Artifact の CSP により外部フォント・外部画像は不可。フォントは上記スタックで近似し、
  その旨をモック内に注記(「本番フォントは別途確認」)。
- 2案は1ページ内に縦並び(案A → 案B)+ 冒頭に選択観点の短い説明(色の有無・余白密度)。
- サンプルデータ例: 8/10(日)21:43 南西→南東・最大仰角 42°・明るさ●●○/
  8/12(火)20:15 トレイン(打ち上げ3日目)・北西→東・最大仰角 61°・明るさ●●●。
- ダミーの地点表示は「東京都千代田区」程度の粒度にする(実在の詳細住所は使わない)。
